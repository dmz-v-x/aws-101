## EC2 Logs

When running applications on EC2 instances, monitoring metrics alone is not enough. Metrics tell you **how the system is performing**, but logs tell you **what is actually happening inside the system**.

Logs are records of events that occur within the operating system or applications running on the EC2 instance.

They help administrators and developers:

- troubleshoot issues
- analyze system behavior
- detect failures
- investigate security incidents

There are two main categories of logs associated with EC2 instances:

- System logs
- Application logs

Each type provides different insights into the system.

---

### 1. System Logs

System logs contain information about events that occur within the **operating system of the EC2 instance**.

These logs record activities related to:

- system startup
- service initialization
- kernel messages
- hardware events
- system errors

System logs are especially useful when diagnosing problems with the instance itself.

Examples of issues that system logs can help identify include:

- instance boot failures
- network configuration problems
- disk errors
- service crashes
- operating system issues

AWS also allows you to retrieve **EC2 instance system logs directly from the AWS console**, even if you cannot connect to the instance.

This is particularly useful when an instance fails during startup.

For Linux systems, common system log files include:

- `/var/log/syslog`
- `/var/log/messages`
- `/var/log/dmesg`
- `/var/log/boot.log`

These logs provide detailed information about the operating system and system-level events.

---

### 2. Application Logs

Application logs record events generated by the **software running on the EC2 instance**.

Unlike system logs, which are produced by the operating system, application logs are generated by specific applications such as:

- web servers
- APIs
- databases
- background services

Application logs typically record information such as:

- incoming requests
- user activity
- errors and exceptions
- processing results
- application performance details

For example, a web server like Nginx may produce logs such as:

- access logs showing incoming requests
- error logs showing failed requests or server errors

Typical application log locations might include:

- `/var/log/nginx/access.log`
- `/var/log/nginx/error.log`
- application-specific log directories

Application logs are essential for:

- debugging software issues
- analyzing user behavior
- monitoring application health
- identifying performance problems

Many organizations send these logs to centralized logging systems such as **CloudWatch Logs** for easier monitoring and analysis.

---

### 3. Summary

Logs provide detailed records of events occurring on EC2 instances and are essential for troubleshooting and monitoring systems.

There are two main types of EC2-related logs:

| Log Type | Purpose |
|------|------|
| System Logs | Record events related to the operating system and instance startup |
| Application Logs | Record events generated by applications running on the instance |

System logs help diagnose infrastructure-level issues, while application logs help analyze the behavior and performance of the software running on the server.

Together, these logs provide a comprehensive view of what is happening inside an EC2 environment.
