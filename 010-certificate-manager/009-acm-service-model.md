## ACM Service Model — Keys, Storage, and HSM-Level Protection (Private CA)

### 1. What Do We Mean by "Service Model"?
The ACM service model explains:
- Who generates and owns the keys
- Where keys are stored
- How securely they are protected
- What level of control you (the user) have

This is critical because:
Certificates = security  
Keys = the most sensitive part

---

### 2. Key Components in ACM

There are three important parts:

1. Private Key  
2. Public Key  
3. Certificate  

Flow:
- Private key → stays secret  
- Public key → shared via certificate  
- Certificate → binds identity + public key  

---

### 3. Key Management in ACM (Managed Certificates)

When you request an ACM-managed certificate:

- ACM generates:
  - Private key
  - Public key
  - CSR
- You NEVER see the private key

Key idea:
Private key is fully managed by AWS

---

### 4. Where Are Keys Stored?

ACM stores private keys in:
→ AWS-managed secure infrastructure

For public certificates:
- Keys are stored securely
- Not accessible to users
- Used only internally for TLS termination

---

### 5. What is HSM (Hardware Security Module)?

An HSM is a special hardware device designed to:
- Store cryptographic keys securely
- Perform cryptographic operations
- Prevent key extraction

Key idea:
Keys never leave the HSM in plain form

---

### 6. HSM-Level Protection in AWS

AWS uses HSM-backed systems (via AWS KMS / CloudHSM concepts):

- Keys are protected using FIPS 140-2 compliant hardware
- Even AWS engineers cannot access your keys
- Operations happen inside secure boundaries

---

### 7. ACM Public Certificates (Key Model)

For ACM public certs:

- Private key:
  - Generated by ACM
  - Stored securely
  - Not exportable

- You:
  - Only reference certificate ARN
  - Attach it to services (ALB, CloudFront)

---

### 8. ACM Private CA (Different Model)

With AWS Private CA:

- You create your own CA
- AWS manages CA private key inside HSM

Key difference:
You control issuance policy, but NOT raw key access

---

### 9. Private CA Key Protection

Private CA keys are:

- Stored in dedicated HSMs
- Protected with strict access control
- Used only for signing certificates

Important:
- You cannot download CA private key
- This prevents catastrophic compromise

---

### 10. Key Lifecycle in Private CA

1. CA key is generated inside HSM  
2. Used to sign intermediate or leaf certs  
3. Never exposed outside  
4. Can be rotated (advanced setup)  

---

### 11. Imported Certificates (Your Responsibility)

If you import a certificate:

- YOU generate private key
- YOU store it before upload
- ACM stores it securely after import

Important:
- ACM does NOT manage renewal
- Security responsibility is shared

---

### 12. Storage Model Summary

| Type                | Key Generated By | Key Visible To You | Storage Location |
|---------------------|------------------|--------------------|------------------|
| ACM Managed (Public)| AWS              | No                 | AWS Secure/HSM   |
| ACM Private CA      | AWS (HSM)        | No                 | HSM              |
| Imported Cert       | You              | Yes                | AWS Secure Store |

---

### 13. Why You Cannot Export Keys (Important)

For ACM-managed certs:

- Private key is non-exportable

Why?
- Prevent leakage
- Enforce security boundaries
- Reduce attack surface

---

### 14. How Certificates Are Used Without Exposing Keys

Example (ALB):

1. Client connects via HTTPS  
2. ALB uses certificate ARN  
3. ALB accesses private key internally  
4. TLS handshake completes  

At no point:
→ You see or handle the key

---

### 15. Security Benefits of ACM Model

- No manual key handling → fewer mistakes  
- HSM-backed protection → strong security  
- Automatic renewal → no expiry issues  
- Tight AWS integration → safe usage  

---

### 16. Limitations of This Model

- No access to private key (managed certs)
- Less flexibility for custom use cases
- Must use AWS-integrated services

---

### 17. When You Need More Control

Use imported certificates when:
- You need private key access
- You use hybrid systems (AWS + on-prem)
- You require special compliance

---

### 18. Real-World Example

Scenario:
You deploy a website using ALB + ACM

- ACM generates cert
- Stores key in secure system
- ALB uses it for HTTPS

You:
- Never touch keys
- Only attach cert ARN

---

### 19. Why This Matters for ACM Mastery

You must understand:
- Where keys live
- Who controls them
- When you can/cannot access them

This helps you:
- Choose correct certificate type
- Design secure architectures
- Avoid critical security mistakes

---

### 20. Key Takeaways

- ACM manages keys for you (in managed certs)
- Private keys are never exposed
- HSM provides strong hardware-level security
- Private CA keys are fully protected in HSM
- Imported certs give you control but more responsibility
- Understanding key ownership = core to security design
