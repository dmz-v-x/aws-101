## Signed URLs & Signed Cookies in CloudFront (Private Content Delivery)

### 1. Why Private Content is Needed

#### 1.1 Problem

By default, CloudFront content is public:

- Anyone with the URL can access content  
- No access control  

---

#### 1.2 Solution

CloudFront provides:

- **Signed URLs**
- **Signed Cookies**

These allow you to:

> Restrict access to only authorized users

---

#### 1.3 Key Insight

> Signed mechanisms ensure that only users with valid authorization can access content

---

### 2. Signed URLs

---

#### 2.1 What is a Signed URL?

A **signed URL** is a URL that includes:

- Expiration time  
- Signature  
- Access policy  

---

#### 2.2 Example

```
https://d123.cloudfront.net/video.mp4?Expires=...&Signature=...&Key-Pair-Id=...
```

---

#### 2.3 How It Works

1. Backend generates signed URL  
2. Sends it to user  
3. User requests CloudFront using that URL  
4. CloudFront verifies signature  
5. If valid → content served  

---

#### 2.4 Use Cases

- One-time downloads  
- Secure file sharing  
- Temporary access to media  

---

#### 2.5 Key Insight

> Each URL is **individually secured**

---

### 3. Signed Cookies

---

#### 3.1 What are Signed Cookies?

Instead of signing each URL:

- You set cookies in browser  
- Cookies contain authentication info  

---

#### 3.2 How It Works

1. User logs in  
2. Backend sets signed cookies  
3. Browser stores cookies  
4. Requests automatically include cookies  
5. CloudFront validates cookies  

---

#### 3.3 Use Cases

- Streaming platforms  
- Multiple file access  
- Session-based authentication  

---

#### 3.4 Key Insight

> One authentication → access to multiple resources

---

### 4. Signed URLs vs Signed Cookies

---

#### 4.1 Comparison Table

| Feature | Signed URL | Signed Cookies |
|--------|-----------|----------------|
| Scope | Single resource | Multiple resources |
| Use case | File download | Streaming / web apps |
| Complexity | Simple | Slightly complex |
| Browser storage | No | Yes |

---

#### 4.2 When to Use Signed URLs

Use when:
- Access to a single file  
- Temporary sharing  
- Simple implementation needed  

---

#### 4.3 When to Use Signed Cookies

Use when:
- Access to multiple files  
- Logged-in user sessions  
- Streaming platforms  

---

### 5. Key Groups & Public Key Infrastructure

---

#### 5.1 Why Keys Are Needed

CloudFront must verify:
> “Was this URL generated by a trusted source?”

---

#### 5.2 Key Pair Concept

- Private key → used to sign  
- Public key → used by CloudFront to verify  

---

#### 5.3 Key Groups

CloudFront uses **Key Groups**:

- A collection of public keys  
- Attached to distribution  

---

#### 5.4 Flow

```
Your Backend → signs using private key  
CloudFront → verifies using public key (in key group)
```

---

#### 5.5 Key Insight

> Never expose private key — only public key goes to CloudFront

---

### 6. Creating Key Pairs & Key Groups

---

#### 6.1 Step 1: Generate Key Pair

You generate:

- Private key (stored securely)
- Public key (uploaded to CloudFront)

---

#### 6.2 Step 2: Upload Public Key

- Go to CloudFront  
- Add public key  

---

#### 6.3 Step 3: Create Key Group

- Add public key to key group  
- Attach key group to distribution  

---

#### 6.4 Step 4: Configure Behavior

- Enable signed URLs or cookies in cache behavior  

---

### 7. Signing URLs Programmatically (Node.js Example)

---

#### 7.1 Install Dependency

```
npm install aws-cloudfront-sign
```

---

#### 7.2 Example Code

```
const cf = require('aws-cloudfront-sign');

const url = "https://d123.cloudfront.net/video.mp4";

const signedUrl = cf.getSignedUrl(url, {
  keypairId: "YOUR_KEY_PAIR_ID",
  privateKeyString: process.env.PRIVATE_KEY,
  expireTime: Math.floor(Date.now() / 1000) + 60 * 60 // 1 hour
});

console.log(signedUrl);
```

---

#### 7.3 Explanation

- `keypairId` → identifies public key  
- `privateKeyString` → used for signing  
- `expireTime` → expiration timestamp  

---

### 8. Signing URLs (Python Example)

---

#### 8.1 Example Code

```
from botocore.signers import CloudFrontSigner
import datetime
import rsa

def rsa_signer(message):
    private_key = rsa.PrivateKey.load_pkcs1(open('private_key.pem').read().encode())
    return rsa.sign(message, private_key, 'SHA-1')

url = "https://d123.cloudfront.net/video.mp4"

expire_date = datetime.datetime.utcnow() + datetime.timedelta(hours=1)

cloudfront_signer = CloudFrontSigner("KEY_PAIR_ID", rsa_signer)

signed_url = cloudfront_signer.generate_presigned_url(
    url,
    date_less_than=expire_date
)

print(signed_url)
```

### 11. Security Best Practices

---

#### 11.1 Protect Private Key

- Store securely (env variables, secrets manager)  
- Never expose in frontend  

---

#### 11.2 Use Short Expiration

- Reduce risk of misuse  

---

#### 11.3 Use HTTPS Only

- Prevent interception  

---

#### 11.4 Rotate Keys Regularly

- Improve security  

---

### 12. Common Mistakes

---

#### Mistake 1: Exposing private key

Leads to:
- Complete security breach  

---

#### Mistake 2: Long expiration times

Leads to:
- Unauthorized prolonged access  

---

#### Mistake 3: Using signed URLs for multiple files

Leads to:
- Inefficiency  

---

#### Mistake 4: Misconfigured key groups

Leads to:
- Access denied errors  

---

### 13. Debugging Issues

---

#### 13.1 Access Denied

- Invalid signature  
- Expired URL  
- Wrong key pair  

---

#### 13.2 Signature Mismatch

- Incorrect private key  
- Incorrect signing algorithm  

---

#### 13.3 Cookie Not Sent

- Missing domain/path settings  
- Browser restrictions  

---

---

#### 14.2 File Download System

### 15. Final Mental Model

> Signed URLs and cookies turn CloudFront into a **secure gatekeeper**, where access is granted only when requests are cryptographically verified.

- Signed URL → one resource, one-time access  
- Signed Cookies → session-based, multi-resource access  

Together, they enable:
- Secure content delivery  
- Controlled access  
- Scalable authorization mechanisms
