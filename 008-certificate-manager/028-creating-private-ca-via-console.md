## Create Your First AWS Private CA (Console — Step by Step)

### 1. What Are We Doing?
We will create a **Private Certificate Authority (CA)** using the AWS Console.

Goal:
- Set up your own CA
- Enable issuing private certificates

---

### 2. Prerequisites

You need:

- AWS account  
- IAM permissions:
  - acm-pca:* (or specific Private CA permissions)
- Decide region (CA is regional)

---

### 3. Step 1 — Open AWS Private CA Console

1. Go to AWS Console  
2. Search: **Private Certificate Authority**  
3. Click: **AWS Private CA**

---

### 4. Step 2 — Click “Create a Certificate Authority”

You’ll see options:

- Root CA  
- Subordinate CA (Intermediate)

For first setup:
→ Select **Root CA**

Click:
→ **Next**

---

### 5. Step 3 — Configure CA Type

Choose:

- General-purpose CA (recommended)

This is used for:
- Internal services  
- Microservices  
- APIs  

---

### 6. Step 4 — Configure CA Details

Fill details:

#### Key Algorithm
- RSA 2048 (recommended default)

#### Signing Algorithm
- SHA256WITHRSA

---

### 7. Step 5 — Configure Subject (Identity)

Enter CA identity:

Example:

- Country: IN  
- Organization: MyCompany  
- Organizational Unit: DevOps  
- Common Name: MyRootCA  

This defines:
→ Who this CA represents

---

### 8. Step 6 — Configure Validity Period

Set how long CA is valid:

Example:
- 10 years (recommended for root CA)

---

### 9. Step 7 — Configure Revocation (Important)

Enable CRL:

- Enable CRL (recommended)  
- Select S3 bucket (create if needed)  

This allows:
→ Revoking certificates later  

---

### 10. Step 8 — Review and Create

Click:
→ **Create CA**

Status:
→ **PENDING_CERTIFICATE**

---

### 11. Step 9 — Activate the CA (Important Step)

After creation:

You must **activate CA**

---

#### Step 9.1 — Get CSR

Click:
→ **Get certificate signing request (CSR)**

Download CSR file

---

#### Step 9.2 — Self-Sign (Root CA)

For root CA:

- Choose **Self-sign CA certificate**

---

#### Step 9.3 — Import Certificate

Upload:

- Signed certificate (generated by AWS for root)

Click:
→ **Activate CA**

---

### 12. Step 10 — CA Status = ACTIVE

Now your CA is ready:

- Can issue certificates  
- Can manage revocation  

---

### 13. What You Just Created

You now have:

- Root Certificate Authority  
- Secure key stored in HSM  
- Ability to issue private certificates  

---

### 14. Next Step (Very Important)

Now you can:

- Issue certificates via ACM  
- Integrate with:
  - ALB  
  - EKS  
  - Internal services  

---

### 15. Best Practice (Production Setup)

Instead of using root CA directly:

Create:

Root CA  
   ↓  
Intermediate CA  
   ↓  
Certificates  

Why:
- Better security  
- Root key used less frequently  

---

### 16. Common Mistakes

- Not activating CA  
- Skipping CRL setup  
- Using wrong region  
- Using root CA directly in production  

---

### 17. Cost Reminder

Private CA:
- Charges start immediately after creation  
- Even if not used  

So:
→ Delete unused CAs  

---

### 18. Real-World Example

Company creates:

- Root CA  
- Issues certificates for:
  - internal.api  
  - service.internal  

Used for:
→ Secure internal communication  

---

### 19. Mental Model

Private CA = Your own certificate factory  

You:
- Control issuance  
- Control revocation  
- Control trust  

---

### 20. Key Takeaways

- Private CA lets you create your own CA  
- Root CA is first step  
- Must activate CA after creation  
- CRL is important for revocation  
- Use intermediate CA in production
